## Critical findings (deduplicated)

### C1. Users can set their own credits and admin flag
**Status:** LIVE on prod.
**Sources:** SEC-1, CR-6

- **Where:**
  - `supabase/migrations/20260705014138_*.sql:15,19` grants `authenticated` UPDATE on the whole `profiles` table.
  - Policy `"Users update own profile"` has no column limit and no WITH CHECK.
  - No trigger guards the credit columns.
- **Production check:** the policy and the UPDATE grant are both present. The only trigger is `set_profiles_updated_at`.
- **Exploit:** from the browser console, `supabase.from('profiles').update({user_credits: 999999, is_admin: true}).eq('id', me)`.
- **Side effects of setting `is_admin`:**
  - The user receives admin Telegram alerts, which contain other users' emails.
  - It unlocks the buyers'-group link.
- **Fix:**
  - `REVOKE UPDATE` on `profiles`, then `GRANT UPDATE` only on the profile fields Settings writes (`settings.tsx:48`).
  - Change `alertAdmins` and buyers-group to use `has_role`.
  - Run a balance-vs-ledger reconciliation.
- **Effort:** <1h, plus reconciliation.

### C2. Users can give themselves any plan, including unlimited
**Status:** LIVE on prod.
**Sources:** SEC-2, CR-6

- **Where:**
  - `20260705192402_*.sql:114-119`: policies `"Users insert own subscription"` and `"Users update own subscription"`.
  - The INSERT and UPDATE grants to `authenticated` are present on production.
- **Exploit:** `update({plan_name:'pro', unlimited_usage:true})`.
  - Every charge becomes 0.
  - Every plan gate opens.
- **Fix:** drop both policies and revoke INSERT/UPDATE/DELETE. The app already writes subscriptions with the service role.
- **Effort:** <1h.

### C3. Any user can add 10,000 credits per call
**Sources:** SEC-3, CR-1, QA-1

- **Where:**
  - `src/lib/credits.functions.ts:12-48`: `refundCreditsFn` takes `amount` and `source` from the client.
  - It then runs `refund_credits` as the service role. Nothing ties the refund to an earlier charge.
- **Fix:**
  - Delete `refundCreditsFn` and the legacy branch at `access.ts:162-167`.
  - Remove the RPC in a new migration.
- **Effort:** <1h.

### C4. Users can refund generations that succeeded
**Status:** the SQL is LIVE on prod.
**Sources:** SEC-4, CR-2, CR-3, QA-2

- **Where:**
  - `refund_credits_by_ledger` (`20260715201121:273`) only skips `refunded` and `failed` rows. Production has the same definition.
  - Three client-callable paths reach it:
    - `refundLedgerFn` (`credits-guard.functions.ts:111`) takes any ledger id.
    - `refundVideoJobCredits` (`video-refund.functions.ts:13-31`) refunds `charged` rows for a job id. The client sets that id through the `x-cf-job` header, which the image, tts and clip routes all accept.
    - `cancelGenerationJobFn` refunds `generation_jobs.ledger_id`, and users can rewrite that column through RLS `jobs_owner_update`.
- **Fix:**
  - Refund only `status='reserved'` rows.
  - Validate job ownership on the server.
  - Remove the user's write access to `ledger_id`.
- **Effort:** <1d.

### C5. Paid AI runs with no server charge, no plan gate, and one endpoint has no login
**Sources:** SEC-5, SEC-6, CR-4, CR-5, CR-7, PERF-6

- **No login:**
  - `planThumbnailBrief` (`thumbnail-planner.functions.ts:71`) has no `requireSupabaseAuth`, so anyone on the internet can burn the OpenRouter key.
- **Charged only by the browser, so calling the endpoint directly is free and skips plan gates:**
  - SEO (`seo-package.functions.ts:119,177`)
  - Business Promo (`promo-video.functions.ts:197,253`)
  - Ad copy (`ad-creative.functions.ts:27`)
- **Never charged:**
  - `reverseEngineerThumbnail`, priced at 1 credit.
  - `analyzeThumbnailQuality`, `scoreAssetFn`, `detectCreativeIntent`, `scoreLinkedinPost` and `shortenVoiceoverLines`.
- **Root cause:** `reserveCreditsFn` accepts the amount and action from the client, accepts an amount of 0, and runs no plan gate.
- **Fix:**
  - Use `chargeMiddleware(<action>)` on every AI server function.
  - Add the missing entries to `ACTION_FEATURE`.
  - Make `ACTION_COSTS` the only price table (CR-17).
  - Retire the client-priced `reserveCreditsFn`.
- **Effort:** <1h for the thumbnail endpoint; <1d for all of them.

## Recommended fix order
1. **Emergency (today), covering C1, C2, C3 and C4.**
   - One migration:
     - Lock `profiles` columns.
     - Drop the subscription write policies.
     - Make `refund_credits_by_ledger` refund only `reserved` rows.
     - Remove the user's write access to `generation_jobs.ledger_id`.
     - Drop `refund_credits`.
   - One server patch: delete `refundCreditsFn`, and restrict `refundLedgerFn` and `refundVideoJobCredits`.
   - Then a read-only reconciliation to find accounts that already abused these holes, before deciding anything about those accounts.
   - **Needs SPK approval:** the migration runs on prod and changes refund logic.
2. **Close free AI, covering C5 and H1.** Charge on the server everywhere, put auth on the thumbnail endpoint, and add a per-user rate limit.
3. **Payments, covering H7, H8 and H6.** Atomic `grant_credits` RPC, a webhook claim that can be retried, and plan expiry with a backfill.
4. **Margins, covering H3, H5, H2 and H4.**
   - H3 and H5 need no price change.
   - H2 (motion clip at about 42 credits) and H4 (length-based script pricing) **need SPK approval** because they change credit costs.
5. **Credit UX, covering H9, H10 and H11.** Reservation sweeper (refund logic, so it needs approval), key consumption and the retry bug.
6. **Tests, covering H13.**
   - Add vitest, a `typecheck` script, and SQL tests for reserve, finalize and refund.
   - Add webhook tests, plus regression tests for C1–C4.
7. **Medium and Low findings.** Start with the hidden-features decision, then H12 (base64 thumbnails), price-table consolidation and the rest.
